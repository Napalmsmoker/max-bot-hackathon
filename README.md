**Бот в MAX:** https://max.ru/t350_hakaton_max_bot
**Git-репозиторий:** https://github.com/Napalmsmoker/max-bot-hackathon

## Назначение решения

Приложение помогает предпринимателям, ИП и самозанятым Курганской области решать повседневные задачи:

- **Проверка контрагентов** — получение данных об организациях и ИП из ЕГРЮЛ, ФНС и арбитражных судов с оценкой рисков.
- **Подбор субсидий** — каталог мер поддержки с фильтрами по отрасли, типу бизнеса и статусу заявки.
- **База знаний** (в разработке) — гайды и статьи по бизнес-процессам.
- **Новости и анонсы** (в разработке) — мероприятия, изменения в законах, новые меры поддержки.

Приложение работает как **мини-приложение внутри мессенджера MAX** и открывается из чат-бота. Такой формат обеспечивает доступ к сервисам без установки отдельного мобильного приложения.

## Целевая аудитория

**Приоритетный сегмент:** начинающие и действующие предприниматели Курганской области.

**Характеристики:**
- ИП, ООО или самозанятые
- Микро- и малый бизнес
- Регион: Курганская область
- Отрасли: производство, IT, торговля, услуги, сельское хозяйство

**Почему эта аудитория:**
- 6,6 млн субъектов МСП зарегистрировано в России (данные ФНС, июль 2026)
- Предпринимателям приходится использовать несколько разрозненных сервисов: МСП.РФ, ЕГРЮЛ, ФНС, региональные фонды
- Интерфейсы этих сервисов не адаптированы под мобильные устройства
- Отсутствует единая точка входа для типовых задач

## Основной пользовательский сценарий

**Цель:** получить данные о контрагенте или подобрать меру поддержки за 2–3 минуты, не выходя из мессенджера MAX.

### Сценарий 1: Проверка контрагента

1. Пользователь открывает бота в MAX → нажимает **«Открыть приложение»**
2. Мини-приложение загружается внутри мессенджера (MAX Bridge передаёт данные пользователя)
3. На главном экране пользователь нажимает **«Проверка контрагента»**
4. Вводит ИНН или название компании
5. Нажимает **«Проверить»**
6. Получает карточку с реквизитами, статусом, рисками

### Сценарий 2: Подбор субсидии

1. На главном экране пользователь нажимает **«Каталог субсидий»**
2. Применяет фильтры: отрасль, тип бизнеса, статус
3. Видит отфильтрованный список мер поддержки
4. Открывает карточку конкретной субсидии
5. Изучает условия и чек-лист документов
6. Отмечает документы, которые уже собрал
7. Переходит на первоисточник (МСП.РФ) по кнопке

### Сценарий 3: Смена темы

1. В правом верхнем углу — кнопка ☀️ / 🌙
2. Нажатие переключает тему
3. Выбор сохраняется в localStorage
4. При следующем открытии тема восстанавливается

## Описание работы с данными

### Откуда берутся данные

- **Все данные — статические**, лежат в `src/data/*.ts`
- **Никаких сетевых запросов** к внешним API не делается
- **Никакой персональной информации** не собирается и не хранится

### Как данные используются

1. **Проверка контрагента:**
   - Пользователь вводит ИНН или название
   - Функция `searchCompanies(query)` ищет совпадения в `mockCompanies`
   - Возвращает первую найденную компанию или пустой массив

2. **Каталог субсидий:**
   - Все субсидии из `mockSubsidies` отображаются в списке
   - Фильтры по отрасли, типу бизнеса, статусу применяются на клиенте через `useMemo`
   - Клик по карточке → переход на `/subsidies/:id`

3. **Тема:**
   - Хранится в `localStorage` под ключом `theme`
   - Значения: `dark` или `light`
   - По умолчанию — `dark`

### Что НЕ делается с данными

- Не отправляется на сервер
- Не логируется
- Не собирается аналитика
- Не используются cookie

В каталоге **7 субсидий** для Курганской области:

5. Льготный микрозайм для МСП (до 5 млн ₽)
6. Субсидия на участие в выставках и ярмарках (до 600 тыс. ₽)
7. Грант «Агротуризм» для сельских территорий (до 10 млн ₽)

**Фильтры:**
- Отрасль: производство, IT, сельское хозяйство, торговля, услуги
- Тип бизнеса: ИП, ООО, самозанятый
- Статус: приём открыт, скоро дедлайн

## Пошаговый сценарий проверки

### 1. Запуск приложения

**Через Docker (рекомендуется):**

```bash
docker compose up --build
```

Открой http://localhost:8080

**Через Vercel (быстрая проверка):**

Открой https://max-bot-hackathon.vercel.app

**Через dev-сервер (для разработки):**

```bash
npm install
npm run dev
```

Открой http://localhost:5173

### 2. Проверка главного экрана

- Видишь заголовок «Бизнес-Навигатор»
- 4 модуля: Проверка контрагента, Каталог субсидий, База знаний (неактивна), Новости (неактивна)
- В правом верхнем углу — кнопка переключения темы
- Внизу — плашка «Хакатон MAX 350 · Бизнес-Навигатор»

### 3. Проверка «Проверка контрагента»

- Нажми **«Проверка контрагента»**
- Введи ИНН `7707083893`
- Нажми **«Проверить»**
- Через 800 мс появится карточка с реквизитами и рисками
- Вернись назад → введи `9999999999` → увидишь «Компания не найдена»

### 4. Проверка «Каталог субсидий»

- Нажми **«Каталог субсидий»**
- Видишь 7 карточек
- Нажми чип **«IT и связь»** → останется 1 карточка
- Сбрось фильтр → нажми **«Производство»** → 1 карточка
- Нажми на любую карточку → детальный экран
- Пролистай: описание, условия, чек-лист документов
- Отметь 2 чекбокса → прогресс-бар заполнится
- Нажми «Открыть на МСП.РФ» → откроется новая вкладка

### 5. Проверка смены темы

- Нажми иконку ☀️ → тема станет светлой
- Обнови страницу (**Ctrl+Shift+R**) → тема осталась светлой
- Нажми 🌙 → тема станет тёмной

### 6. Проверка Docker-сборки

```bash
docker compose up --build
```

- Сборка должна занять **не более 5 минут**
- После сборки контейнер `business-navigator` запущен
- Приложение доступно на порту **8080**

## Известные ограничения

### Данные
- **Все данные тестовые.** Реальные интеграции с ЕГРЮЛ, ФНС, МСП.РФ не подключены. В UI это явно обозначено плашкой.
- **Нет бэкенда.** Все данные — на клиенте, ничего не сохраняется между сессиями, кроме темы.

### Модули
- **«База знаний»** — кнопка неактивна (модуль в разработке).
- **«Новости и анонсы»** — кнопка неактивна (модуль в разработке).

### Платформа MAX
- **Сертификат Минцифры** — для работы с реальным API MAX требуется установить корневой сертификат Минцифры в доверенные (требование с сентября 2026).
- **Верификация в MAX** — привязка URL мини-приложения к боту возможна только через профиль организации / ИП / самозанятого.
- **Ник бота не изменяется** после создания — это ограничение платформы MAX.
- **Токен бота** — не хранится на фронтенде (не нужен), используется только бэкендом (отсутствует в MVP).

### Совместимость
- Протестировано в **Chrome**, **Яндекс.Браузер**, **Safari**.
- На мобильных устройствах работает при открытии через MAX.
- При открытии в обычном браузере MAX Bridge не загружается (`window.WebApp` = `undefined`) — это ожидаемое поведение.

## Порядок остановки и повторного запуска решения

### Остановка контейнера

```bash
docker compose down
```

Контейнер `business-navigator` останавливается и удаляется. Данные не сохраняются (их нет).

### Повторный запуск без пересборки

```bash
docker compose up
```

Контейнер запустится за несколько секунд (образ уже собран).

### Полная пересборка (после изменений в коде)

```bash
docker compose up --build
```

Docker заново соберёт образ из исходников. Это нужно после изменения файлов в `src/`.

### Просмотр логов

```bash
docker compose logs -f frontend
```

### Полная очистка (включая образ)

```bash
docker compose down --rmi all
```

После этого следующий `docker compose up --build` соберёт всё с нуля.
