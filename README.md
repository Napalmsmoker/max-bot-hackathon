## Назначение решения

Приложение помогает предпринимателям, ИП и самозанятым Курганской области решать повседневные задачи:

- **Проверка контрагентов** — данные об организациях и ИП из ЕГРЮЛ, ФНС и арбитражных судов с оценкой рисков. Работает через **бэкенд API** (FastAPI).
- **Подбор субсидий** — каталог мер поддержки с фильтрами по отрасли, типу бизнеса и статусу заявки.
- **База знаний** — 8 статей с гайдами по бизнес-процессам: регистрация, налоги, найм, экспорт, маркетинг.
- **Новости и анонсы** — лента мероприятий, изменений в законах, новых мер поддержки.

Приложение работает как **мини-приложение внутри мессенджера MAX** и открывается из чат-бота. Такой формат обеспечивает доступ к сервисам без установки отдельного мобильного приложения.

**Особенность:** проверку контрагента можно выполнить **двумя способами**:
1. Через **бота в MAX** — просто отправив ИНН сообщением.
2. Через **мини-приложение** — удобный интерфейс с фильтрами и карточками.

Данные синхронизированы между ботом и приложением — оба используют один и тот же бэкенд API.

## Целевая аудитория

**Приоритетный сегмент:** начинающие и действующие предприниматели Курганской области.

**Характеристики:**
- ИП, ООО или самозанятые
- Микро- и малый бизнес
- Регион: Курганская область
- Отрасли: производство, IT, торговля, услуги, сельское хозяйство

**Почему эта аудитория:**
- 6,6 млн субъектов МСП зарегистрировано в России (данные ФНС, июль 2026)
- Предпринимателям приходится использовать несколько разрозненных сервисов: МСП.РФ, ЕГРЮЛ, ФНС, региональные фонды
- Интерфейсы этих сервисов не адаптированы под мобильные устройства
- Отсутствует единая точка входа для типовых задач

## Основной пользовательский сценарий

**Цель:** проверить контрагента или подобрать меру поддержки за 2–3 минуты, не выходя из мессенджера MAX.

### Сценарий 1: Проверка контрагента через бота

1. Пользователь открывает бота в MAX: `https://max.ru/t350_hakaton_max_bot`
2. Отправляет `/start`
3. Бот отвечает приветствием и **кнопкой «🔍 Открыть приложение»**
4. Пользователь отправляет ИНН сообщением — например, `7707083893`
5. Бот возвращает результат скоринга: название, статус, индекс надёжности, риски, рекомендации

### Сценарий 2: Проверка контрагента через мини-приложение

1. Пользователь нажимает **«🔍 Открыть приложение»** в боте
2. Открывается мини-приложение внутри MAX
3. На главном экране нажимает **«Проверка контрагента»**
4. Вводит ИНН или название компании
5. Получает карточку с реквизитами, статусом, рисками
6. **Данные совпадают с теми, что вернул бот** — оба запрашивают один бэкенд

### Сценарий 3: Подбор субсидии

1. На главном экране нажимает **«Каталог субсидий»**
2. Применяет фильтры: отрасль, тип бизнеса, статус
3. Открывает карточку субсидии
4. Изучает условия и чек-лист документов
5. Переходит на первоисточник (МСП.РФ)

### Сценарий 4: Работа с базой знаний и новостями

1. Открывает **«База знаний»** → 8 статей по 6 категориям
2. Открывает **«Новости и анонсы»** → 8 новостей, важные помечены рамкой

### Сценарий 5: Смена темы

1. В правом верхнем углу — кнопка ☀️ / 🌙
2. Нажатие переключает тему
3. Выбор сохраняется в localStorage

### Взаимодействие компонентов

1. **Пользователь пишет боту `/start`** → MAX отправляет событие в бэкенд (Long Polling)
2. **Бэкенд отвечает** → отправляет сообщение с кнопкой `web_app` через `/messages`
3. **Пользователь нажимает кнопку** → MAX открывает мини-приложение (Vercel) внутри мессенджера
4. **Мини-приложение вызывает API** → `POST https://max-production-172f.up.railway.app/api/v1/counterparty/check`
5. **Бэкенд возвращает данные** → фронт рендерит карточку компании
6. **Данные совпадают** → бот и приложение используют один источник — `provider.py`

## Описание работы с данными

### Откуда берутся данные

**Проверка контрагентов:**
- Источник: `max-backend/app/services/provider.py` — словарь `MOCK_DATA`
- Два тестовых ИНН + генерация fallback для неизвестных
- Возвращается структурированный JSON (Pydantic-модель `CounterpartyCheckResponse`)

**Субсидии, статьи, новости:**
- Источник: `frontend/src/data/mock*.ts` — статические данные
- Все данные на клиенте, без сетевых запросов

### Как данные используются

1. **Проверка контрагента — бот:**
   - Пользователь отправляет ИНН
   - Бот вызывает `get_counterparty_data(inn)`
   - Формирует текстовый ответ и отправляет в чат

2. **Проверка контрагента — мини-приложение:**
   - Пользователь вводит ИНН
   - Фронт вызывает `POST /api/v1/counterparty/check` на Railway
   - Получает JSON → конвертирует в формат фронта (`counterparty.ts`)
   - Рендерит карточку `CompanyCard`

3. **Тема:**
   - Хранится в `localStorage` под ключом `theme`

### Что НЕ делается с данными

- Персональные данные не собираются
- Cookie не используются
- Аналитика не подключена

## Известные ограничения

### Данные
- **Проверка контрагента** — моки в `provider.py`. Реальные ЕГРЮЛ/ФНС не подключены.
- **Субсидии, статьи, новости** — моки на клиенте.

### Платформа MAX
- **Сертификат Минцифры** — для работы с реальным API MAX требуется установить корневой сертификат Минцифры в доверенные (требование с сентября 2026).
- **Верификация в MAX** — привязка URL мини-приложения к боту возможна только через профиль организации / ИП / самозанятого.
- **Ник бота не изменяется** после создания — ограничение платформы.

### Бэкенд
- **Нет базы данных** — данные в памяти контейнера (Python dict).
- **Long Polling** — для MVP. Для production рекомендуется Webhook.

### Совместимость
- Протестировано в Chrome, Яндекс.Браузер, Safari.
- На мобильных устройствах работает при открытии через MAX.

## Порядок остановки и повторного запуска решения

### Фронтенд

```bash
cd frontend
docker compose down          # остановить
docker compose up            # запустить
docker compose up --build    # пересобрать
```

### Бэкенд

```bash
cd max-backend
docker compose down          # остановить
docker compose up            # запустить
docker compose up --build    # пересобрать
```

### Просмотр логов

```bash
docker compose logs -f       # в папке нужного сервиса
```

### Полная очистка

```bash
docker compose down --rmi all
```
