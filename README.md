## Назначение решения

Приложение помогает предпринимателям, ИП и самозанятым Курганской области решать повседневные задачи:

- **Проверка контрагентов** — получение данных об организациях и ИП из ЕГРЮЛ, ФНС и арбитражных судов с оценкой рисков.
- **Подбор субсидий** — каталог мер поддержки с фильтрами по отрасли, типу бизнеса и статусу заявки.
- **База знаний** — 8 статей с гайдами по бизнес-процессам: регистрация, налоги, найм, экспорт, маркетинг.
- **Новости и анонсы** — лента мероприятий, изменений в законах, новых мер поддержки.

Приложение работает как **мини-приложение внутри мессенджера MAX** и открывается из чат-бота. Такой формат обеспечивает доступ к сервисам без установки отдельного мобильного приложения.

## Целевая аудитория

**Приоритетный сегмент:** начинающие и действующие предприниматели Курганской области.

**Характеристики:**
- ИП, ООО или самозанятые
- Микро- и малый бизнес
- Регион: Курганская область
- Отрасли: производство, IT, торговля, услуги, сельское хозяйство

**Почему эта аудитория:**
- 6,6 млн субъектов МСП зарегистрировано в России (данные ФНС, июль 2026)
- Предпринимателям приходится использовать несколько разрозненных сервисов: МСП.РФ, ЕГРЮЛ, ФНС, региональные фонды
- Интерфейсы этих сервисов не адаптированы под мобильные устройства
- Отсутствует единая точка входа для типовых задач

## Основной пользовательский сценарий

**Цель:** получить данные о контрагенте, подобрать меру поддержки или найти нужную информацию за 2–3 минуты, не выходя из мессенджера MAX.

### Сценарий 1: Проверка контрагента

1. Пользователь открывает бота в MAX → нажимает **«Открыть приложение»**
2. Мини-приложение загружается внутри мессенджера
3. На главном экране нажимает **«Проверка контрагента»**
4. Вводит ИНН или название компании
5. Нажимает **«Проверить»**
6. Получает карточку с реквизитами, статусом, рисками

### Сценарий 2: Подбор субсидии

1. На главном экране нажимает **«Каталог субсидий»**
2. Применяет фильтры: отрасль, тип бизнеса, статус
3. Видит отфильтрованный список мер поддержки
4. Открывает карточку конкретной субсидии
5. Изучает условия и чек-лист документов
6. Отмечает документы, которые уже собрал
7. Переходит на первоисточник (МСП.РФ) по кнопке

### Сценарий 3: Работа с базой знаний

1. На главном экране нажимает **«База знаний»**
2. Выбирает категорию (регистрация, налоги, найм, экспорт, маркетинг)
3. Открывает статью
4. Читает гайд с разделами, списками и выделенными блоками
5. Возвращается к списку или переходит к другим статьям

### Сценарий 4: Просмотр новостей

1. На главном экране нажимает **«Новости и анонсы»**
2. Видит ленту: важные новости помечены рамкой и меткой «ВАЖНО»
3. Фильтрует по категории (мероприятия, законы, поддержка, экономика)
4. Открывает новость
5. Изучает детали и переходит на первоисточник (ФНС, МСП.РФ)

### Сценарий 5: Смена темы

1. В правом верхнем углу — кнопка ☀️ / 🌙
2. Нажатие переключает тему
3. Выбор сохраняется в localStorage
4. При следующем открытии тема восстанавливается

## Описание работы с данными

### Откуда берутся данные

- **Все данные — статические**, лежат в `src/data/*.ts`
- **Никаких сетевых запросов** к внешним API не делается
- **Никакой персональной информации** не собирается и не хранится

### Как данные используются

1. **Проверка контрагента:**
   - Пользователь вводит ИНН или название
   - Функция `searchCompanies(query)` ищет совпадения в `mockCompanies`
   - Возвращает первую найденную компанию или пустой массив

2. **Каталог субсидий:**
   - Все субсидии из `mockSubsidies` отображаются в списке
   - Фильтры по отрасли, типу бизнеса, статусу применяются на клиенте
   - Клик по карточке → переход на `/subsidies/:id`

3. **База знаний:**
   - Статьи из `mockArticles` фильтруются по категории
   - Клик по карточке → переход на `/knowledge/:id`
   - Контент рендерится простым markdown-парсером (H2, списки, жирный текст)

4. **Новости:**
   - Новости из `mockNews` сортируются по дате (новые сверху)
   - Фильтруются по категории
   - Важные помечаются рамкой и меткой

5. **Тема:**
   - Хранится в `localStorage` под ключом `theme`
   - Значения: `dark` или `light`
   - По умолчанию — `dark`

### Что НЕ делается с данными

- Не отправляется на сервер
- Не логируется
- Не собирается аналитика
- Не используются cookie

## Известные ограничения

### Данные
- **Все данные тестовые.** Реальные интеграции с ЕГРЮЛ, ФНС, МСП.РФ не подключены. В UI это явно обозначено плашкой.
- **Нет бэкенда.** Все данные — на клиенте, ничего не сохраняется между сессиями, кроме темы.

### Модули
- **Все 4 модуля активны и работают.**
- Контент (статьи, новости) — тестовый, для MVP.

### Платформа MAX
- **Сертификат Минцифры** — для работы с реальным API MAX требуется установить корневой сертификат Минцифры в доверенные.
- **Верификация в MAX** — привязка URL мини-приложения к боту возможна только через профиль организации / ИП / самозанятого.
- **Ник бота не изменяется** после создания — ограничение платформы MAX.
- **Токен бота** — не хранится на фронтенде (не нужен).

### Совместимость
- Протестировано в Chrome, Яндекс.Браузер, Safari.
- На мобильных устройствах работает при открытии через MAX.
- При открытии в обычном браузере MAX Bridge не загружается — это ожидаемо.
